## 用户故事

**作为** 系统管理员，**我希望** 为 API 配置请求控制策略（用户级互斥 + 滑动窗口限流），**以便** 防止同一用户并发重复提交、突发高频请求影响系统稳定性。

## 需求描述

1. 密码有效期保持现状，不随本功能改动
2. API 请求控制配置：`iam_api.request_control` 以 JSON 字符串存储，管理端 API 编辑页提供表单区进行可视化编辑
3. 用户级互斥：同一用户对同一 API 的前一个请求未完成时，拒绝其下一个请求
4. 滑动窗口频率限制：基于 Redis 实现滑动窗口，窗口内请求数超限则拒绝
5. 默认值配置化：全局开关、互斥超时、限流窗口与上限均可通过 `application.yml` 调整

## 验收标准

1. `iam_api` 表新增 `request_control` TEXT 列，存储互斥/限流 JSON 配置
2. 管理端 API 编辑页（create/update）可编辑请求控制表单区，详情展示配置
3. `RequestControlFilter` 仅对登录用户生效，按 API 级配置执行互斥与限流
4. 互斥冲突返回 429「请求处理中，请稍后重试」（fail-closed）
5. 限流超限返回 429「请求过于频繁，请稍后重试」（fail-open，Redis 异常放行）
6. 默认值来自 `iam.request-control.*` 配置，可在 `application.yml` 修改

## 表结构变更

```sql
ALTER TABLE iam_api ADD COLUMN request_control TEXT COMMENT '请求控制配置(JSON)' AFTER write_flag;
```

- 存储格式：JSON 字符串（实体 `IamApi.requestControl` 直接存字符串，Req/Resp 层用 `ApiRequestControl` 对象，Rest 层通过
  fastjson2 转换：`JSON.toJSONString` / `JSON.parseObject`）

## 配置项

| 配置                                              | 说明         | 默认值  |
|-------------------------------------------------|------------|------|
| `iam.request-control.enabled`                   | 全局开关       | true |
| `iam.request-control.mutex.timeout-seconds`     | 互斥锁超时时间（秒） | 30   |
| `iam.request-control.rate-limit.window-seconds` | 限流滑动窗口（秒）  | 60   |
| `iam.request-control.rate-limit.max-requests`   | 窗口内最大请求数   | 100  |

> `IamRequestControlConfig` 默认值设计：`enabled` 为全局开关（默认 true），`mutex` / `rateLimit` 无全局 enable（由各 API 的
> JSON 配置决定是否启用）。

## JSON 配置结构示例

```json
{
  "enable": true,
  "mutex": {
    "enable": true,
    "timeoutSeconds": 30
  },
  "rateLimit": {
    "enable": true,
    "windowSeconds": 60,
    "maxRequests": 100
  }
}
```

## 行为说明

- 仅登录用户生效（未登录用户不参与请求控制）
- 互斥：fail-closed——同一用户请求未完成即再次请求同一 API，锁冲突返回 429「请求处理中，请稍后重试」
- 限流：fail-open——滑动窗口内请求数超限返回 429「请求过于频繁，请稍后重试」；Redis 异常时放行（不阻断业务）
- 过滤器链（自外向内）：`RequestRecordFilter(MAX-10) → SessionAuthFilter(MAX-5) → RequestControlFilter(MAX)`（MAX =
  `Ordered.LOWEST_PRECEDENCE` = `Integer.MAX_VALUE`）

## 技术实现要点

- `RequestControlResolver`：解析 API 请求控制配置（JSON → `ApiRequestControl`），判断是否启用互斥/限流
- `SlidingWindowRateLimiter`：基于 Redis ZSet 的滑动窗口限流实现
- `ApiControlCache`：API 请求控制配置缓存（Guava Cache 5min + AntPathMatcher 最长匹配）
- `RequestControlFilter`：请求控制过滤器（互斥 RedisLock + 滑动窗口限流，拒绝返回 429，`@Order(Ordered.LOWEST_PRECEDENCE)`（无
  +1，+1 会溢出为最小值导致排到链最外层））
- `SsoApiControlMapper`：查询 API 请求控制配置（含 XML）
- 管理端 API 编辑页增加请求控制表单区，create/update 时随 `request_control` JSON 一并提交
