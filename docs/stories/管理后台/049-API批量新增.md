# STORY-049 — API 批量新增（代码扫描入库）

## 用户故事

**作为** 系统管理员， **我希望** 通过扫描运行时代码中的 REST 接口，以表格形式列出可入库的接口，勾选并补全信息后批量或单条入库，
**以便** 快速将代码中的接口纳管到权限系统，避免逐个手动新增。

## 需求描述

1. 功能入口：API 管理页右上角「批量新增」按钮，打开扫描结果弹窗
2. 扫描结果：调用 `RestHelper.getMapping()` 获取运行时代码中全部 REST 接口，表格展示应用编码、模块、请求方法、URI、接口名称、白名单、排序、备注、状态
3. 入库状态标记：已在库的接口（按 `apiMethod + apiUri` 匹配）状态列为「已入库」，选择框禁用；未在库的为「可新增」，可勾选
4. 补全信息：接口名称（扫描有值则预填，无值必填）、白名单（扫描默认值可调整）、排序（默认
   99）、备注（可选）；appCode/module/apiMethod/apiUri 只读
5. 搜索条件：弹窗顶部支持按模块、请求方法、URI、接口名称、入库状态 **后端过滤**（条件提交后端，减少返回数据量）
6. 单条入库：每条「可新增」行提供「入库」按钮，仅提交该行，成功后该行刷新为已入库
7. 批量提交：勾选多行后一键提交，提交前校验 apiName 非空；后端逐条校验 `apiMethod + apiUri` 全局唯一性，成功项入库、失败项返回原因
8. 重复性校验：已在库或同批重复的 method+uri 跳过入库，不影响其他项

## 验收标准

1. 「批量新增」按钮在 API 管理页右上角可见，点击打开弹窗
2. 弹窗打开时调用扫描接口，表格展示全部扫描接口，列完整
3. 已在库行选择框 disabled，状态显示「已入库」
4. 未在库行可勾选，apiName/writeFlag/sort/remark 可编辑
5. 搜索条件提交后端过滤，返回匹配结果；重置后重新加载全部
6. 单条入库成功后该行状态变为已入库，选择框禁用，弹窗不关闭
7. 批量提交成功行刷新为已入库，响应返回成功/失败条数
8. 已存在或同批重复的 method+uri 不入库，库中无重复记录

## 技术实现要点

- `GET /iam-admin/api/scan`（`ApiScanReq`/`ApiScanResp`）：`IamApiService.scanApis(req)` 调用 `RestHelper.getMapping()`，按
  appCode/module/apiMethod/apiUri (模糊)/apiName (模糊)/exists 后端过滤后，查询库中已存在的 `method+uri` 集合，逐条标记
  `exists` 与 `existingId`
- `POST /iam-admin/api/batch-create`（`ApiBatchCreateReq`/`ApiBatchCreateResp`）：`IamApiService.batchCreate()` 逐条校验
  apiName 非空、method+uri 不与库中/本批已收录项重复；通过项生成 apiCode（`RedisIdGenerator`），`mapper.insertBatch` 批量入库；按
  appCode 发布 `PermissionChangeEvent.appChanged`
- 唯一性键：`apiMethod.toUpperCase() + "|" + apiUri`，与 `duplicateCheck` 语义一致
- 前端：`api.js` 新增 `apiScan`/`apiBatchCreate`；`index.vue` 右上角新增「批量新增」按钮；新增 `components/batch-add.vue`
  （搜索条件区 + 可编辑表格 + 单条/批量提交）

## 边界与异常

- 批量入库为部分成功模式：重复/缺名校验失败的项跳过，成功项正常落库
- 单条与批量共用同一后端接口（items 列表长度为 1 即单条）
- 批量新增不涉及 requestControl（默认 null/关闭），创建后可通过编辑弹窗单独配置
- apiCode 由后端自动生成，前端无需提供
