## 用户故事

**作为** 系统管理员，**我希望** 将菜单树（含各节点绑定的接口引用）以 JSON 导出到剪贴板、并从剪贴板导入，**以便** 在环境间迁移菜单结构及其接口引用，支持递归复制任意子树。

## 需求描述

1. 功能入口：菜单管理页树形视图下方左侧提供「导出」下拉（导出全部 / 导出选中）与「导入」按钮，样式与 API 页一致；表格首列前增加勾选列，勾选父节点自动带全部子孙
2. 导出：结果为标准 JSON，顶层仅包含菜单数组（树形嵌套结构），节点内以 `apiCodes`（仅接口编码）附加绑定接口，不携带接口定义、字段权限、角色-菜单关联
3. 导入：模态弹窗内使用 monaco-editor 作为 JSON 编辑器（语法高亮）；按 `menuCode` 判断存在性——存在更新、不存在新增，业务数据全程无删除
4. 绑定语义：绑定关系**不做接口存在性过滤**——目标库暂不存在的接口编码同样写入 `iam_menu_api` 关系表，待接口后续经 STORY-044 导入成功后绑定自动生效；对「JSON 中显式携带 `apiCodes` 字段的菜单」的绑定做全量快照重建（仅关系表先清后插）
5. 校验：内存校验全部通过后才落库——顶层必须为非空菜单数组；节点必填 `menuCode`、`menuName`；`menuType` 必须 ∈ MENU/BUTTON/FIELDS；文件内 `menuCode` 不得重复；`parentCode` 引用必须存在于文件内或目标库；`apiCodes` 各项必须为非空字符串（仅格式校验）；任一不合法整体阻止导入并逐条「第 N 项：xxx」提示
6. 禁止循环查库：导出两次批量查询（菜单 1 次 + 绑定 1 次），导入批量查询划分新增/更新后分块批量落库；递归仅存在于内存运算

## 验收标准

1. 「导出选中」时后端依据 `parentCode` 内存递归补齐全部子孙节点（前端勾选行为兜底），导出 JSON 包含该子树完整树形结构
2. 「导出全部」按 `appCode` 导出当前应用全部菜单树，无分页限制
3. 导入根节点的 `parentCode` 若既不在文件内也不在目标库中，自动置为 `"0"`（顶级）并在结果中提示（`parentFixHints`）
4. 新增菜单按树序先父后子走 `insertBatch`；更新走 `updateBatch4Import`（CASE WHEN 逐行设值单 SQL）；分块 200 条/批
5. 绑定全量快照重建：对显式携带 `apiCodes` 的菜单先 `deleteByMenuCodes` 清除现有绑定，再将 `apiCodes` 全量批量入表；节点 `apiCodes` 缺失（字段不存在）不动其现有绑定；导入过程不查询、不改动 `iam_api`
6. 同一份 JSON 重复导入幂等：菜单均走更新路径，绑定重建后状态与 JSON 一致，无重复数据
7. 导入返回新增/更新菜单数、重建绑定数与 `parentCode` 修复提示明细，成功后刷新菜单树
8. 前端提交前执行与后端一致的前置校验（解析失败/非数组/节点必填/menuType 枚举/menuCode 重复/parentCode 引用缺失/apiCodes 空值逐条列明，整体阻止）

## 导出 JSON 结构示例

```json
[
  {
    "appCode": "app_x",
    "parentCode": "0",
    "menuCode": "menu_a",
    "menuName": "系统管理",
    "icon": "system",
    "menuType": "MENU",
    "routePath": "/system",
    "component": null,
    "buttonCode": null,
    "hidden": 0,
    "remark": null,
    "sort": 1,
    "apiCodes": ["api_a", "api_b"],
    "children": [
      { "...": "递归子节点，结构同父节点" }
    ]
  }
]
```

## 技术实现要点

- `GET /iam-admin/menu/export`（`MenuExportReq`：`ids` + `appCode` / `MenuExportResp`）：`ids` 有值时 `selectByIds` 批量取选中节点后按 `parentCode` 内存递归补齐全部子孙；否则按 `appCode` 全量查询。绑定关系 `IamMenuApiMapper.getBindingsByMenuCodes` 一次 IN 查询，内存按 menuCode 分组挂接为 `apiCodes`——两次批量查询，无循环查库
- `POST /iam-admin/menu/import`（`MenuImportReq`/`MenuImportResp`）：`@Transactional` 内先内存校验（全部通过才落库），再按树序先序遍历划分新增/更新：新增走 `insertBatch`（先父后子）、更新走自定义 XML `updateBatch4Import`（CASE WHEN 逐行设值单 SQL），分块 200/批（Guava `Lists.partition`）
- 绑定全量快照重建：对显式携带 `apiCodes` 的菜单，`IamMenuApiMapper.deleteByMenuCodes` 先删后 `insertBatch` 全量插入（分块 200/批）；不做接口存在性过滤，目标库暂缺的接口待 API 导入迁移成功后自动生效
- 菜单数据全程无删除，仅绑定关系表允许先清后插
- 前端：`api.js` 新增 `menuExport`/`menuImport`；`index.vue` 树形视图新增勾选列（勾选父节点自动带全部子孙）与底部左侧导出下拉（loading 态）/导入按钮；新增 `components/import.vue`（monaco-editor + 前置校验 + `parentFixHints` 告警提示，提示语位于编辑器下方），请求级错误由 ui-core request 拦截器统一弹出

## 边界与异常

- 批量操作分块 200，循环仅用于内存递归分组、先序遍历与分块
- 操作全程 loading：导出按钮 loading、导入确定按钮 loading
- JSON 解析失败、校验失败、请求异常统一捕获提示，不崩页；请求级错误由全局拦截器提示
- 导出结果复制到系统剪贴板（无文件下载），并提示导出条数；列表视图不新增勾选列（导出选中仅基于树形视图）

## 排除项

- 接口定义、字段权限不随菜单导出/导入（接口迁移使用 STORY-044 API 导出/导入）
- 菜单字段组绑定（`iam_menu_field`）不随导出/导入（FIELDS 类型菜单节点本身会导出，其字段绑定不在范围）
- 角色-菜单关联（`iam_role_menu`）不在导出/导入范围
