## 用户故事

**作为** 系统管理员，**我希望** 将数据维度（单表、无关联）以 JSON 导出到剪贴板、并从剪贴板导入，**以便** 与 API（STORY-044）、菜单（STORY-046）同方案在环境间迁移数据维度定义，支持勾选导出与全量导出。

## 需求描述

1. 功能入口：数据维度页表格首列前增加勾选列，表格下方左侧（分页行旁，与 API 页相同布局位置）提供「导出」下拉（导出全部 / 导出选中）与「导入」按钮
2. 导出：结果为标准 JSON，顶层仅为维度数组；节点包含全部业务字段 `appCode`/`dimensionCode`/`dimensionName`/`dimensionDataJson`/`dimensionScript`/`remark`/`sort`，其中 `dimensionDataJson`/`dimensionScript` 为维度核心载荷，完整导出
3. 导出查询语义：`ids` 有值→按主键批量导出勾选项；否则按页面筛选条件（`appCode` 精确 + `dimensionCode`/`dimensionName` 模糊，与列表查询同语义）全量导出，无分页
4. 导入：模态弹窗内使用 monaco-editor 作为 JSON 编辑器（语法高亮，提示语位于编辑器下方）；按 `dimensionCode` 判断存在性——存在更新、不存在新增，业务数据全程无删除；单表导入，不涉及任何关联表
5. 校验：内存校验全部通过后才落库——顶层必须为非空数组；每项 `appCode`、`dimensionCode`、`dimensionName` 必填；文件内 `dimensionCode` 不得重复；`dimensionDataJson` 若提供（非空白）必须是合法 JSON（可解析）；任一不合法整体阻止导入并逐条「第 N 项(xxx)：原因」提示
6. 顺带修复：`IamDataDimensionService.duplicateCheck` 缺陷——现实现误将 `dimensionCode` 写入 `appCode` 字段查询导致唯一性校验失效，修正为按 `dimensionCode` 校验
7. 禁止循环查库：导出一次批量查询（选中模式 `selectByIds` 一次）；导入一次 IN 批量查询划分新增/更新后分块批量落库，循环仅用于内存划分与分块

## 验收标准

1. 「导出选中」仅导出勾选行的完整维度数据（含 `dimensionDataJson`/`dimensionScript`），结果复制到系统剪贴板并提示条数
2. 「导出全部」按当前筛选条件导出全部维度，无分页限制
3. 使用专用全列查询 `getDims4Export`，既有轻量分页查询 `getDataDimensionList` 保持不动（刻意不含 `dimension_data_json`/`dimension_script` 两列以保持分页轻量）
4. 新增维度走 `insertBatch`；更新走 `updateBatch4Import`（CASE WHEN 逐行设值 + version 自增，不更新 `dimension_code`，`update_time` 由数据库填充）；分块 200 条/批
5. 导入返回新增条数、更新条数明细，成功后刷新列表
6. 同一份 JSON 重复导入幂等：维度均走更新路径，无重复数据
7. 校验失败整体阻止：任一项缺少 `appCode`/`dimensionCode`/`dimensionName`、`dimensionCode` 重复或 `dimensionDataJson` 非 JSON，均不落任何数据，逐条给出明细
8. 修复后创建已存在 `dimensionCode` 的维度返回 RECORD_DUPLICATE（修复前漏判放行）；导入路径不经过该单条校验（由导入自身批量去重保证）
9. 前端提交前执行与后端一致的前置校验（解析失败/非数组/必填缺失/编码重复/`dimensionDataJson` 非法 JSON 逐条列明，整体阻止），全程 loading 态

## 导出 JSON 结构示例

```json
[
  {
    "appCode": "app_x",
    "dimensionCode": "dim_city",
    "dimensionName": "城市维度",
    "dimensionDataJson": "[{\"label\":\"北京\",\"value\":\"110000\"}]",
    "dimensionScript": "select code, name from city",
    "remark": null,
    "sort": 1
  }
]
```

## 技术实现要点

- `GET /iam-admin/data-dim/export`（`DataDimExportReq`：`ids`/`appCode`/`dimensionCode`/`dimensionName` + `DataDimExportResp`）：`ids` 有值→`selectByIds` 一次批量导出勾选项；否则走专用全列查询 `getDims4Export`（含 `dimension_data_json`/`dimension_script` 全部业务列）。既有轻量分页查询 `getDataDimensionList` 刻意不含该两列，故保持不动、导出使用新查询。结果内存转换，无循环查库
- `POST /iam-admin/data-dim/import`（`DataDimImportReq`/`DataDimImportResp`）：`@Transactional` 内先内存校验（必填/文件内 `dimensionCode` 去重/`dimensionDataJson` 合法 JSON，全部通过才落库），再 `getDimsByCodes` 一次 IN 批量查询已存在维度划分新增/更新：新增分块 `insertBatch`、更新分块 `updateBatch4Import`（CASE WHEN 逐行设值单 SQL，不更新 `dimension_code`），分块 200/批（Guava `Lists.partition`），返回 `insertCount`/`updateCount`，全程无删除
- 顺带修复 `duplicateCheck`：将误设到 `appCode` 字段的唯一条件修正为 `dimensionCode`，单条创建/更新唯一性校验恢复生效
- 前端：`dim.js` 新增 `datadimExport`/`datadimImport`；顺带修复 `datadimCreate`/`datadimUpdate`/`datadimRemove` 形参与 `data` 引用不一致导致的调用即错缺陷；`index.vue` 新增勾选列与底部左侧导出下拉（loading 态）/导入按钮；新增 `components/import.vue`（monaco-editor + 前置校验，提示语位于编辑器下方），请求级错误由 ui-core request 拦截器统一弹出

## 边界与异常

- 批量操作分块 200，循环仅用于内存划分与分块，无循环查库
- 操作全程 loading：导出按钮 loading、导入确定按钮 loading
- JSON 解析失败、校验失败、请求异常统一捕获提示，不崩页；请求级错误由全局拦截器提示
- 导出结果复制到系统剪贴板（无文件下载），并提示导出条数

## 排除项

- 维度无关联关系，不涉及绑定/树形递归/关系表处理
- 数据维度-角色关联（`iam_role_data`）不在导出/导入范围
