## 用户故事

**作为** 系统管理员，**我希望** 所有非公开的 API 请求都经过 JWT + Redis 会话双重校验，**以便** 确保只有已登录且会话有效的用户才能访问受保护的资源。

## 验收标准

1. 继承 `OncePerRequestFilter`，每个请求只过滤一次
2. 无条件设置 appCode + tenantCode（每个请求，来自请求头）
3. `/*/public/**` 路径的请求直接放行
4. 从请求头获取 Token（Authorization: Bearer 或 token 头）
5. 非白名单 + Token 缺失 → 401 "缺少认证 Token"
6. 非白名单 + 无有效会话 → 401 "会话无效或已过期"（JWT 过期、登出后 Redis 会话已删均被拦截）
7. 准入判断唯一依据是完整会话验证（`SessionManager.validateAndRefresh`：JWT 有效 + Redis 会话存在）
8. 白名单接口在无有效会话时 best-effort 解析 claims（`TokenService.parseClaimsBestEffort`），仅用于审计日志，不作为准入依据
9. 校验通过后设置 `IdentityContext`（userIdentity + token）
10. 不调用 `IdentityContext.clear()`（由外层 `RequestRecordFilter` 的 finally 负责）

## 技术实现要点

- 过滤器链执行顺序：RequestRecordFilter（最外层，Order=LOWEST_PRECEDENCE-10）→ SessionAuthFilter → Controller
- 公开路径匹配使用 Ant 风格：`/**/public/**`（可配置 `iam.session.white-list`）
- Token 获取逻辑：优先 `Authorization` 头（去掉 `Bearer ` 前缀），其次 `token` 头
- 准入逻辑（2026-08-18 修复）：**非白名单接口仅认完整会话**，JWT 过期或 Redis 会话不存在（含登出后）一律 401；
  `parseClaimsBestEffort` 兜底仅用于白名单接口的审计身份提取，不再作为准入依据，避免"过期/登出 token 仍可访问接口"的问题
